# Proof-Carrying Data Analyst (HNX26PSI08)

An agent that answers questions about messy retail sales data and **proves every number**:
each answer ships with a standalone Python script that anyone can re-run to get the same
figure. When the data cannot support an answer, the agent says so instead of guessing.

## What it does

1. **Profiles** the raw files and lists every data-quality problem (`profile_data.py`).
2. **Triages** each question into `ANSWER`, `ANSWER_WITH_ASSUMPTIONS`, `CLARIFY` or `REFUSE`
   *before* computing anything (missing columns, dates outside the data, ambiguous dates,
   unclear periods, unsupported groupings).
3. **Writes a script** (cleaning prelude + analysis) to `answers/<id>.py`.
4. **Executes it** in a separate process, then **executes it a second time** and compares.
5. **Reports** the answer, the assumptions applied, evidence (rows and orders used), the data
   problems fixed along the way, a confidence value, and cross-document conflicts.
6. `verify.py` re-proves every saved answer in a brand-new temporary folder.

## Technologies

Python 3.10+, pandas, numpy. Optional: Streamlit (UI) and the Anthropic API (free-form
questions). No other libraries or datasets are used.

## Install and run

```
py -m pip install -r requirements.txt            (Mac/Linux: python3 -m pip ...)
py generate_data.py                              build the messy dataset (data/) and answer key (eval/)
py profile_data.py                               data-health report
py ask.py "What was net revenue in March 2025?"  ask one question
py eval.py                                       score the agent on all 18 test questions
py verify.py                                     re-run every saved script in a clean folder
```

Optional UI:

```
py -m pip install -r requirements-extra.txt
py -m streamlit run app.py
```

Optional free-form mode (LLM writes the pandas code; same execution and verification path):

```
set ANTHROPIC_API_KEY=your-key        (PowerShell: $env:ANTHROPIC_API_KEY="your-key")
py ask.py --llm "Which category grew fastest from Q1 to Q2?"
```

## Reproduce the demonstrated results

`py generate_data.py && py eval.py && py verify.py` prints `18 / 18` and `18 / 18 answers
re-proven`. The same holds for other seeds (`py generate_data.py --seed 7`).

## The dataset (synthetic, generated by `generate_data.py`)

Four tables plus a finance report, with traps planted at known rates:

| Trap | Where | How the agent handles it |
|---|---|---|
| Exact duplicate order rows (40) | orders | dropped before counting |
| Same customer under two ID formats (10) | customers, orders | IDs compared ignoring case and hyphens |
| Three date formats, incl. DD/MM/YYYY | orders | each parsed separately; slash order proven day-first by rows like 27/03/2025 |
| Mixed currencies USD, EUR, INR | orders | converted with `fx_rates.csv`, rates stated in the answer |
| Discount as 0.10 in some rows, 10 in others | order_items | values above 1 divided by 100 |
| Returns as negative quantities (63) | order_items | reduce revenue, feed the return rate |
| Status spelled 12 ways | orders | normalised |
| Orders for customers that do not exist (15) | orders | kept in revenue, excluded from customer figures |
| `total_amount` wrong on 34 orders | orders | ignored; order lines used |
| Unit price differs from product list price (15) | order_items | price actually charged is used |
| Missing country / category | customers, products | excluded / reported as Unknown |
| Finance report contradicts the tables (Q3) | finance_report.txt | tables used, conflict flagged |

`eval/` holds the answer key and trap counts and is never read by the agent.

## Sample input and output

Input: `py ask.py "What was total revenue for Q3 2025?"`

```
Decision  : ANSWER_WITH_ASSUMPTIONS   (mode: rules, confidence: 0.74)
Response  : Net revenue for Q3 2025 is USD 317,410.08.
Assumptions and checks:
  - Net revenue = quantity x unit_price x (1 - discount) ... delivered and shipped orders only ...
  - Converted non-USD amounts to USD using fx_rates.csv (1 EUR = 1.08 USD, 1 INR = 0.012 USD).
  - Removed 40 exact duplicate order rows before counting.
  - ... (discounts rescaled, status normalised, dates parsed, unknown customers noted)
  - CONFLICT: finance_report.txt says USD 355,000 for Q3 2025 but the order tables give
    USD 317,410.08 (report is +11.8% off). The tables were used because they can be
    recomputed line by line; the report figure cannot be reproduced.
Script    : answers/A0db8ae05.py (reproducible: True)
```

Other behaviours (all in `answers/answers.json` after `py eval.py`):

- "What was the revenue on 04/05/2025?" -> `CLARIFY`: 4 May or 5 April?
- "What was revenue in Q4 2025?" -> `REFUSE`: data ends 2025-09-30.
- "What is our profit margin?" -> `REFUSE`: no cost columns exist.
- "Why did sales drop in June compared to May?" -> premise is false: June was 3.9% higher.

## Evidence and explanation per answer

Each result contains: `answer`, `summary`, `assumptions`, `evidence` (order lines and orders used),
`data_quality` (what was cleaned and how many rows), `confidence`, `script`, and `reproducible`.
Confidence is a simple heuristic: it starts at 0.97, drops 0.01 per data adjustment applied, and drops
0.15 when two sources conflict. It is a transparency signal, not a calibrated probability.

## Project layout

profile_data.py    data-health report          agent/planner.py        triage and question -> analysis mapping

## Scope note

**Minimum viable (built and tested):** messy multi-table dataset with planted traps; answers with
runnable scripts; refusal of unanswerable questions; clarification of ambiguous dates and periods;
false-premise check; re-execution check; clean-folder verifier; evaluation harness.

**Stretch (built):** data-health profiler; assumption ledger on every answer; cross-document
contradiction detection (finance report vs tables); category-level evidence for "why" questions;
Streamlit UI; optional LLM code generation with a run-and-self-repair loop.

**Not built / known limits:**
- Offline mode understands about ten question types (revenue, by month, by category, order counts,
  top customers, distinct customers, average order value, return rate, top country, month comparison).
  Anything else is answered with a clarification request, or by the LLM if a key is set.
- The LLM path was tested with a mocked model (code failing once, then repairing); it has not been run
  against the live API in this repository.
- The refusal rules are keyword based (costs, delivery, city, marketing, ...). A paraphrase that avoids
  the keywords would not be caught offline.
- The second check is re-execution plus an internal consistency assertion (category and month totals
  must sum to total revenue); there is no independent second implementation of the cleaning.
- The questions in `answer_key.json` shaped the templates, so 18/18 is not a blind-test score.
